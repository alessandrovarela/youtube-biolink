# Story 3.3 — CRUD de links no dashboard

## Status

**Ready for Review** — implementada pelo `@dev` (Dex) em modo YOLO. CRUD completo com 4 Server Actions validadas inline + `sanitizeLinkUrl`, limite de 30, optimistic em criar/toggle, confirmação de deleção inline. Testes unit + integração verdes. Pronta para `@qa`.

---

## Story

**Como** usuário autenticado,
**eu quero** criar, listar, editar e deletar meus links,
**para que** eu componha minha página pública.

---

## Acceptance Criteria

> Fonte canônica: `docs/prd.md` § 6 — Epic 3, Story 3.3. Catálogo de actions: `architecture.md` § 5.2.

1. Página `/dashboard/links` lista links do usuário ordenados por `position`.
2. Form inline no topo para criar link: `title`, `url` (usa helper da Story 3.2).
3. Cada link na lista tem: campos editáveis inline, toggle `is_active`, botão deletar (com confirmação).
4. Server Actions: `createLink`, `updateLink`, `deleteLink`, `toggleLinkActive` — todas validadas com **checks TS inline + helper de URL (`sanitizeLinkUrl`)**. _(Reconciliação: a arquitetura decidiu validação inline sem `zod`; ver Dev Notes.)_
5. Limite: máximo 30 links por usuário (retorna erro claro ao criar 31º).
6. Feedback inline em sucesso/erro; optimistic updates onde seguro (criar, toggle).
7. Testes unitários das Server Actions (mockando client Supabase) + teste de integração contra `development`.

## Dev Notes

> **CRITICAL:** Convenções vêm de `architecture.md`. Nada inventado (Artigo IV).

### ⚠️ Reconciliação PRD × Arquitetura — validação sem `zod`
O PRD (AC4) pede `zod`, mas a arquitetura decidiu **"Inline TS + helpers puros — Zero dependência"** (§ 2.5, § 3.1) e o Epic 2 foi construído assim (nenhum `zod` no `package.json`). **A arquitetura prevalece** (é mais recente; mesmo racional da reconciliação middleware→layout guard do Epic 2). Validar com checks TS inline + `sanitizeLinkUrl` (Story 3.2). **Não adicionar `zod`.** [Source: architecture.md § 2.5, § 3.1; precedente Story 2.10]

### Catálogo de Server Actions (§ 5.2)
Nomes canônicos: `createLink({ title, url })`, `updateLink({ id, title?, url? })`, `deleteLink({ id })`, `toggleLinkActive({ id, is_active })`. Revalidação `('/dashboard/links')` + `('/[username]', 'page')`. [Source: architecture.md § 5.2]

### Authz app-layer
Toda action: `getUser()` → filtro `profile_id = user.id` (sem RLS no MVP). Teste de integração prova que A não altera links de B. [Source: architecture.md § 2.5, § 5.1; prd.md Story 3.1 AC3]

### Limite de 30 links
`createLink` conta os links do usuário antes de inserir; 31º retorna `ActionResult` de erro claro em pt-BR. [Source: prd.md Story 3.3 AC5]

### Dashboard protegido
`/dashboard/links` fica sob o auth guard de layout (`app/dashboard/layout.tsx`, Story 2.9). Anônimo → redirect `/login`. [Source: architecture.md § 8.2]

### Dependências
Depende de **3.1** (tabela `links`) e **3.2** (`sanitizeLinkUrl`). Wave 2 (paralela com 3.5). É base da **3.4** (reorder estende esta lista).
