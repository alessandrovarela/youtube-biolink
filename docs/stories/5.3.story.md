# Story 5.3 — Tracking de clique na página pública

## Status

**Ready for Review** — implementada pelo `@dev`. typecheck/lint/test/build verdes. Aguarda QA Gate (`@qa`).

---

## Story

**Como** dono de uma biolink,
**eu quero** que cada clique nos meus links da página pública seja registrado,
**para que** eu tenha dados de analytics (Epic 5) sem prejudicar a navegação do visitante.

---

## Acceptance Criteria

> Fonte canônica: `docs/prd.md` § 8 — Epic 5, Story 5.3.

1. Cada link da página pública é envolvido por um componente CLIENT que intercepta o `onClick` e dispara `trackLinkClick(linkId)` antes de navegar. Como os links abrem em nova aba (`target="_blank"`), a página permanece aberta e o disparo completa — fire-and-forget (sem `await` bloqueante, resultado ignorado, try/catch para nunca quebrar).
2. A navegação NUNCA é bloqueada se o tracking falhar (offline, erro) — o `<a href>` faz seu trabalho normalmente.
3. Acessibilidade preservada: continua um `<a href>` real. `Ctrl/Cmd+Click`, middle-click e Enter por teclado funcionam. SEM `preventDefault` e SEM navegação programática via JS.
4. Refatoração mantém visual/markup idêntico ao Epic 4 (`TrackedLink` client reusa as mesmas classes/tokens; `PublicProfileView` continua server e renderiza um componente client por link).
5. Teste (RTL): clicar dispara `trackLinkClick` com o linkId correto (action mockada); o link mantém `href`, `target=_blank`, `rel=noopener noreferrer`; tracking que rejeita NÃO lança/quebra.

## Dev Notes

### Fire-and-forget, best-effort
`trackLinkClick` (Story 5.2) já nunca lança e resolve o client anônimo internamente. Ainda assim, no client envolvemos em `void trackLinkClick(id).catch(() => {})` + try/catch — defesa em profundidade: um clique jamais deve segurar ou quebrar a navegação. [Source: PRD Story 5.3 AC1/AC2; lib/actions/track-click.ts]

### Acessibilidade / comportamento nativo
NÃO usamos `preventDefault` nem `router.push`/`window.open`. O disparo acontece em `onClick` (cobre left-click e Enter por teclado) e `onAuxClick` (middle-click); o browser segue o `href` nativamente. Isso preserva Ctrl/Cmd+Click, middle-click e teclado. [Source: PRD Story 5.3 AC3]

### Fronteira server/client
Só `TrackedLink` é `'use client'`. `PublicProfileView` e a RSC `app/[username]/page.tsx` continuam server components — importar um client component numa server component não força a página a dinâmica, então o ISR (`revalidate = 60`) da página pública é preservado (confirmado no `pnpm build`: rota `/[username]` server-rendered com ISR). [Source: architecture.md § 3.1 Cache]

### Nota de ambiente (dev server / Turbopack)
`pnpm dev` retorna HTTP 500 em TODAS as rotas por um erro PRÉ-EXISTENTE de compilação de CSS no Turbopack (Tailwind v4 gera `var(--shadow-sm/md)` inválido a partir de `shadow-[var(--shadow-sm)]` + `hover:shadow-[var(--shadow-md)]`, classes usadas desde o Epic 4 em Card/Toast/nav/PublicProfileView). Confirmado reproduzindo no branch limpo (via `git stash`) — NÃO é regressão da 5.3. O `pnpm build` (produção) compila e gera as páginas estáticas normalmente. Débito a endereçar fora desta story.
