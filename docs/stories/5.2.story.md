# Story 5.2 — Server Action de tracking de clique

## Status

**Ready for Review** — implementada pelo `@dev` (Wave Analytics). typecheck/lint/test verdes (165 testes). Aguarda QA Gate (`@qa`).

---

## Story

**Como** dev,
**eu quero** uma Server Action que registre clique no link,
**para que** a página pública dispare tracking sem expor endpoint público cru.

---

## Acceptance Criteria

> Fonte canônica: `docs/prd.md` § 6 — Epic 5, Story 5.2.

1. `lib/actions/track-click.ts` (`'use server'`) exporta `trackLinkClick(linkId: string)`.
2. Valida que `linkId` é UUID válido e que o link **existe** e está `is_active = true` **antes** de inserir (evita lixo). Inválido/inexistente/inativo → retorno tipado de erro (não lança).
3. INSERT em `link_clicks` com client server-side **sem SERVICE_ROLE** (a tabela não tem RLS no MVP — Story 5.1 AC3 — logo INSERT direto funciona). Como o clicador é anônimo, usa client apropriado para contexto público (`createPublicClient`, stateless, sem cookies de sessão).
4. Captura o user-agent via `headers()` de `next/headers` e trunca a ≤120 chars antes de gravar (`user_agent_short`). `user_agent_hash` = null (stretch). Sem IP raw.
5. _(deferido para Epic 6)_ Rate limiting → Story 6.4. Não aplicável no MVP.
6. Retorna `{ ok: true }` ou erro tipado; **nunca** lança exceção para o client (try/catch interno, sempre graceful).
7. Testes unitários (mock do client Supabase + `headers()`) e teste de integração contra `development` (skip condicional sem creds).

## Dev Notes

> **CRITICAL:** Nada inventado (Artigo IV). Padrão de Server Action de `lib/actions/links.ts` + `ActionResult`.

### Decisão: client do INSERT anônimo (importante para Story 5.3)
O PRD AC3 menciona `createServerClient`, mas o clicador da página pública é um **visitante anônimo sem sessão**. `createServerClient()` exige cookies de sessão e força render dinâmico — inadequado. Usei **`createPublicClient()`** (o mesmo client stateless anon da leitura pública, Story 3.5): sem cookies, sem RLS no MVP, INSERT direto com a anon key funciona. **A Story 5.3 deve reusar `trackLinkClick` como está** — a action já resolve o client internamente; o componente client só precisa chamá-la.

### Localização do arquivo
`lib/actions/track-click.ts` (co-locado com `lib/actions/links.ts`), não `app/actions/` do PRD — alinhado à estrutura real do projeto (todas as Server Actions vivem em `lib/actions/`).

### Validação e privacidade
UUID validado por regex (v1–v5) antes do banco. UA truncado a 120 (paridade com `CHECK (char_length(user_agent_short) <= 120)` da Story 5.1 — última linha de defesa). Sem IP raw. `user_agent_hash` fica null (stretch não obrigatório).

### Graceful (AC6)
`try/catch` externo garante que erro de banco, de contexto (`headers()` fora de request) ou qualquer exceção vire `ActionResult` de erro — um clique jamais quebra a navegação do visitante.

### Sem RLS / Sem rate limiting no MVP
RLS de `link_clicks` → Story 6.3 (a action será refatorada lá para `security definer`/RPC). Rate limiting → Story 6.4.

### Dependências
Story 5.1 (tabela `link_clicks`) e 3.1 (`links`). Ambas aplicadas em dev.
