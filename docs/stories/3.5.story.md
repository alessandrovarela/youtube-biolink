# Story 3.5 — Página pública `/@username` via SSR

## Status

**Ready** — validada pelo `@po` (GO 10/10). Pronta para `@dev`.

---

## Story

**Como** visitante,
**eu quero** acessar `/@username` sem login e ver a página pública do usuário,
**para que** eu clique nos links que me interessam.

---

## Acceptance Criteria

> Fonte canônica: `docs/prd.md` § 6 — Epic 3, Story 3.5. Routing: `architecture.md` § 2.5 + `routing.md` (Story 3.6).

1. Rota `app/[username]/page.tsx` renderiza via RSC. _(Path real é `/[username]`; `@` é display-only — ver Story 3.6.)_
2. Query busca `profile` por `username` (case-insensitive, via `citext`) + links ativos ordenados por `position`.
3. Renderização inclui: avatar (com fallback), display_name, bio, lista de links ativos.
4. Links abrem em nova aba com `rel="noopener noreferrer"`.
5. Username inexistente retorna 404 (via `notFound()` do Next) com página de erro custom `not-found.tsx`.
6. Meta tags: `<title>{display_name} (@{username})</title>`, `description={bio}`, OG image placeholder (definitivo em Phase 2).
7. Cache: `revalidate = 60` na página ou `cache-control: s-maxage=60, stale-while-revalidate=300`.
8. Validação manual do fluxo completo documentada em comentário do PR (smoke test consolidado vive na Story 5.6).

## Dev Notes

> **CRITICAL:** Roteamento e workflow vêm de `architecture.md`. Nada inventado (Artigo IV).

### Estrutura de rota
`app/[username]/page.tsx` + reserved-list (Story 3.6). Rotas internas vencem por precedência; o `@` é display-only (path é `/username`). NÃO usar middleware rewrite no MVP. [Source: architecture.md § 2.5; routing.md — Story 3.6]

### Workflow público (§ 8.3)
`SELECT profile + active links` **sem auth** (leitura pública). O filtro `is_active = true` no próprio query garante que inativos nunca aparecem. [Source: architecture.md § 8.3; prd.md Story 3.1 AC3]

### Case-insensitive
`username` é `citext` (Story 2.1), logo o match por username já é case-insensitive no banco. [Source: architecture.md § 9.2]

### OG image
Placeholder no MVP; imagem definitiva é Phase 2. Não bloquear a story por asset visual. [Source: prd.md Story 3.5 AC6]

### Dependência de dados para smoke
Não **code-depende** de 3.3, mas para o smoke manual precisa de links criados (seed manual ou via dashboard 3.3). O smoke consolidado ponta a ponta vive na Story 5.6. [Source: prd.md Story 3.5 AC8]

### Dependências
Depende de **3.1** (tabela `links`) e **3.6** (decisão/estrutura de rota). Wave 2 (paralela com 3.3).
