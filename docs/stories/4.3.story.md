## Status

**Ready for Review** — implementada pelo `@dev`. typecheck/lint/test/build verdes (136 testes). Aguarda QA Gate (`@qa`).

## Story

**Como** usuário autenticado,
**eu quero** escolher entre os temas light/dark/accent no meu painel,
**para que** a aparência do dashboard reflita minha preferência e fique persistida.

---

## Acceptance Criteria

1. Card "Aparência" em `/dashboard` com 3 swatches clicáveis (preview visual de light/dark/accent) conforme `theme-selector.html`. Usa o `Card` da 4.2 e indica o tema atualmente selecionado.
2. Server Action `updateTheme(theme)` em `lib/actions/profile.ts`: valida `theme ∈ {light,dark,accent}` (inline, sem zod), persiste em `profiles.theme` filtrando por `auth.uid()`. Retorno tipado (`ActionResult`).
3. Aplicação instantânea no dashboard SEM reload via `ThemeProvider` client-side, que seta a classe `theme-dark`/`theme-accent` no `<html>`. O tema inicial vem do `profile.theme` lido server-side no `app/dashboard/layout.tsx` (classe aplicada já no SSR, sem flash).
4. Fallback `light` se o valor do DB for inválido — helper puro `resolveThemeClass(theme?: string): string` reutilizável (retorna `''` para light, `theme-dark`/`theme-accent`) em `lib/theme.ts`. A Story 4.4 reusa na página pública.
5. Teste unitário do helper (todos os casos + inválido→light) e da validação do `updateTheme`. Teste de integração do update (persistência + CHECK do banco).

## Dev Notes

### Classes de tema (Story 4.1)
`app/globals.css`: light = `:root` (sem classe), dark = `html.theme-dark`, accent = `html.theme-accent`. `resolveThemeClass` retorna `''` para light (default via `:root`).

### No-flash (SSR)
O `<html>` é renderizado no root layout, que não conhece o tema. Como o tema já é conhecido server-side no `dashboard/layout.tsx`, o `ThemeProvider` renderiza um `<script>` síncrono (`document.documentElement.classList.add(<classe>)`) antes dos filhos — aplica a classe no primeiro parse, sem flash. Trocas em runtime usam `useTheme().setTheme` (sem reload).

### Authz app-layer
`updateTheme` segue o padrão de `updateProfile`: filtro `.eq('id', user.id)`. Sem RLS no MVP (Epic 6).

### Defense in depth
`resolveTheme`/`resolveThemeClass` toleram valores inválidos do banco (fallback light) além do CHECK `profiles.theme IN ('light','dark','accent')` da baseline.

### Helper para a Story 4.4 (página pública)
`lib/theme.ts` → `resolveThemeClass(theme?: string | null): string` (e `resolveTheme`, `isTheme`, `Theme`, `THEMES`). Puro, sem dependências de client/React.
