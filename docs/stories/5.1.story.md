## Story

**Como** dev,
**eu quero** uma tabela `link_clicks` append-only com FK para `links` e índice adequado,
**para que** o sistema tenha onde registrar cliques (Story 5.2) e agregá-los como analytics, sem coletar dados sensíveis.

## Dev Notes

> **CRITICAL:** Modelo vem de `docs/architecture/ER.md`. Nada inventado (Artigo IV).

### Append-only e privacidade
Um registro por clique, sem UPDATE/DELETE no fluxo normal. **Não** há coleta de IP raw nem UA completo: `user_agent_short` é o UA truncado (≤120 chars, garantido pelo CHECK como última linha de defesa; a truncagem primária é da Server Action da Story 5.2). `user_agent_hash` fica nullable, reservado para dedup futura.

### Sem RLS no MVP
RLS/policies de `link_clicks` são a Story 6.3 (Epic 6). Autorização aqui é **app-layer**: a leitura de analytics faz join `link_clicks → links → profiles` e filtra pelo dono (`auth.uid()`). Documentado no cabeçalho da migration. [Source: ER.md — Regras de autorização no MVP]

### Relacionamento
`link_clicks.link_id → links.id ON DELETE CASCADE`. Deletar o link (ou o profile, em cascata) remove os cliques. [Source: architecture/ER.md]

### Baseline reusada
`gen_random_uuid()` (pgcrypto) já existe (baseline Story 1.4). Não recriar.

### Dependências
Depende da Story 3.1 (`links`). Sem novas dependências npm.
