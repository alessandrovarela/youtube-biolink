# Story 4.2 — Primitivos UI + migração de páginas e navegação do dashboard

## Status

**Ready for Review** — implementada pelo `@dev`. Primitivos criados a partir das specs visuais, páginas de auth/dashboard migradas, topbar/nav coeso adicionado. typecheck/lint/test/build verdes. Aguarda QA Gate (`@qa`).

---

## Story

**Como** usuário do dashboard e visitante,
**eu quero** uma biblioteca de componentes de UI coesa (botões, inputs, cards, avatar, toasts) e uma navegação clara no dashboard,
**para que** a experiência seja consistente com o design system (Story 4.1), acessível e com as features alcançáveis.

---

## Acceptance Criteria

1. Criar em `components/ui/`: `Button.tsx`, `Input.tsx`, `Textarea.tsx`, `Card.tsx`, `Avatar.tsx`, `Label.tsx`, `Toast.tsx`, consumindo os tokens da Story 4.1.
2. **Button**: variants `primary|secondary|ghost|destructive`; sizes `sm|md|lg`; `disabled` e estado `loading` (spinner). `<button>` real, `type` correto, acessível (`aria-busy`).
3. **Input/Textarea**: props `label`, `error`, `hint`; erro visível com `aria-invalid` e `aria-describedby` ligando ao erro/hint.
4. **Avatar**: fallback com iniciais do `display_name` quando `src` ausente ou falha de carregamento (404).
5. **Toast**: top-right, auto-dismiss 5s, `role="status"` (sucesso/info) / `role="alert"` (erro). Client component.
6. **Label**: associável via `htmlFor`.
7. Cada primitivo com teste unitário em `tests/unit/`.
8. Migrar páginas de auth e dashboard para os primitivos (refactor leve). Nenhuma feature funcional regride (auth, CRUD de links, perfil).
9. Navegação/layout coeso do dashboard: topbar/nav ligando **perfil ↔ /dashboard/links** + logout, respeitando `--topbar-h` e `--max-dashboard`. Auth guard do layout intacto.

## Dev Notes

### Tokens (Story 4.1)
Primitivos consomem os tokens via utilities do Tailwind 4 mapeadas do `@theme inline` (`bg-accent`, `text-accent-fg`, `bg-muted`, `text-muted-fg`, `border-border`, `bg-surface`, `text-danger/success/info/warning`, `rounded-md/lg/pill`) e vars diretas onde não há utility (`shadow-[var(--shadow-sm/md)]`, `--topbar-h`, `--max-dashboard`). Foco visível já é global (`*:focus-visible` no globals.css).

### Decisões
- **Sem dependências novas**: helper `cn` local em vez de clsx/cva; sem libs de UI (Artigo IV / restrição da story).
- **`SubmitButton` absorvido pelo `Button`**: pending agora vem do 3º retorno de `useActionState` (`[state, action, pending]`), eliminando `useFormStatus`.
- **`Field` absorvido pelo `Input`** (label+erro+hint, com `hint` novo).
- **Reset de estado sem effect**: `Avatar` (reset de falha quando `src` muda) e `profile-form` (disparo do toast) usam o padrão "ajuste de estado durante o render" do React, satisfazendo `react-hooks/set-state-in-effect`.
- **Logout único**: `LogoutButton` refatorado para `Button ghost` e reusado na `nav` (sem duplicar o form da Server Action).
- **Layout**: o `<main>` centralizado passou para o `layout.tsx`; as pages renderizam apenas conteúdo (evita `<main>` aninhado). Guard de auth preservado.

### Débito da retro do Epic 3
A topbar com tabs Perfil/Links torna as features alcançáveis a partir de qualquer rota do dashboard — fecha o item "a feature é alcançável?".
