### DDL canônico (copiar deste bloco)

[Source: architecture.md § 9.3]
```sql
CREATE TABLE public.links (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  profile_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  title text NOT NULL CHECK (char_length(title) BETWEEN 1 AND 60),
  url text NOT NULL CHECK (url ~ '^https?://'),
  position int NOT NULL DEFAULT 0,
  is_active boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz
);

CREATE INDEX idx_links_profile_position
  ON public.links (profile_id, position);

CREATE TRIGGER links_set_updated_at
  BEFORE UPDATE ON public.links
  FOR EACH ROW
  EXECUTE FUNCTION public.set_updated_at();
```

### Interface TS `Link`

[Source: architecture.md § 4.2] — co-locada em `lib/types.ts` (não há arquivo central de tipos; os tipos de domínio deste projeto são co-locados).

### Sanitização de URL

A CHECK `url ~ '^https?://'` é última linha de defesa (só valida scheme). A sanitização primária (`sanitizeLinkUrl`, rejeição de `javascript:`/`data:`) fica em `lib/validation.ts` na **Story 3.2**. [Source: architecture.md § 9.3 nota]

### Sem RLS nesta story

Autorização é app-layer no MVP — mutações filtram por `profile_id` do dono. RLS em `links` é escopo do Epic 6. O teste de integração valida esse isolamento app-layer sem depender de RLS. [Source: architecture.md § 9.3; prd NFR3]

### Dependências

- Função `public.set_updated_at()` já existe da baseline (Story 1.4) — apenas referenciada.
- Tabela `public.profiles` já existe (Story 2.1) — alvo da FK.
